# Data generation: train/test split and leakage control

Same procedure as persistent_exfiltrate_health: templates + entity pools, disjoint split by seed.

## Procedure (reproducible, no leakage)

1. **Templates.** We define five similar templates for the step-4 user message (tax-related: filing status, W-2, 1099, interest, dividends, home office, deductions, charity, student loan, etc.) in `templates.yaml` with placeholders.

2. **Entity pools.** We define one pool per placeholder category (tax_year, filing_status, city_state, employer, amounts, banks, charity, loan servicer, etc.) in `entity_pools.yaml`. Each pool has at least five entries so they can be split into five disjoint sets.

3. **Random split (seeded).** For a given run with seed \(s\):
   - Shuffle the five templates and assign one to the optimization (train) set and four to the held-out test set.
   - Shuffle each entity pool and partition it into five disjoint subsets (subset 0 = train, subsets 1–4 = test).

4. **Filling instances.** The train instance is generated by filling the chosen train template with entities from subset 0 only. Each test instance is generated by filling its chosen test template with entities from the corresponding test subset. No entity is shared between train and test.

5. **Reproducibility.** Same seed and same YAML files yield the same train/test split and filled messages.

## Files

- `templates.yaml` – five template strings with placeholders.
- `entity_pools.yaml` – per-category lists of entities (at least five per category).
- `generate_persistent_exfiltrate_tax.py` – implements the above; run with `--config config.yaml`.
